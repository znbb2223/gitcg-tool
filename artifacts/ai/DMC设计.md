# DMC 自对弈 · 完整设计（2026-11-28）

> 目标：训一个**不依赖搜索**的动作打分器 Q(s,a)，用整局胜负当标签；先跑出基线 v0，
> 200 局 A/B 对比现有搜索基线，达到门槛就继续迭代，否则回退到冻结线。

## 0. 验收门槛

| 检查 | 口径 | 门槛 |
|---|---|---|
| 管线正确性 | 单局张数/形状/落盘/断点 | 不崩、维度对得上、能续跑 |
| 离线质量 | 按局划分的 val MSE / 符号一致率 | val_sign ≥ 65% |
| 对启发式 | 镜像配对 208 局 | **≥ 55%** 才算学到东西 |
| 对冻结线搜索（150ms） | 镜像配对 208 局 | **≥ 50%** 才算不退化 |
| sanity | DMC vs DMC 104 局 | 50% ± 10%（排除座位偏差） |

低于门槛 → 回退冻结线（`artifacts/ai/snapshots/ai-freeze-2026-11-28/`），不硬推。

## 1. 形态

- **Q(s,a)**：输入 `[状态 44 维 | 动作 8 维]`，输出一个标量 ∈ (-1,1)；同一局面对所有候选各算一次，取最高。
- 网络：44+8 → 64(ReLU) → 32(ReLU) → 1(tanh)，约 3.6k 参数，导出约 60KB JSON。
- **复用 `policy.ts` 的权重格式与 `policyScores` 推理**：`{stateDim, actionDim, usesScore, actionKinds, mean, std, layers}`，
  所以推理端零新格式，`dmc.ts` 只做候选池 + ε-greedy 包装。
- 动作特征：`k`（类别 one-hot 6 维）+ `cost/dmg/kill/fast/tgtHp/end`（6 维）+ `sc`（启发式分，1 维，v0 带上）。

## 2. 前置修正：特征去泄漏（必须先做）

`stateFeatures` 的第 42 维 `deckPriorDiff` 目前是：

```
deckPriorOf(me) - deckPriorOf(enemy)      // deckPriorOf 读 player.initialPile
```

对手的 `initialPile` 是**隐藏信息**，等于把"对手带的是哪 30 张"漏给网络。改法：

- 我方：照旧用自己牌堆的卡牌/角色胜率先验（自己的牌组自己知道，合法）；
- 对手：只用**公开信息（场上三个角色）**，取牌组库中同角色套牌的卡牌胜率均值（按角色组合缓存），
  找不到同队套牌时取 0（中性）。
- 维度保持 44 不变（旧模型不会因维度保护失效），但该维**语义改变**，需在文档里记一笔。

> 顺便说明：这与昨天搜索的 `realisticHidden` 是同一类问题——凡是喂给 AI 的特征，都要过一遍"这是不是公开信息"。

## 3. 采样设计

### 3.1 行为策略（两段）

| 轮次 | 行为策略 | 目的 |
|---|---|---|
| R0 | **纯启发式**（`evaluate.ts` 单步打分，不搜索） | 冷启动：先看合理对局长什么样，避免从随机棋开始 |
| R1~R3 | **ε-greedy 自对弈**：`argmax Q`，ε 概率在候选池里随机 | 让数据分布随网络一起进化 |

不用搜索 AI 采样：2500ms/手比启发式贵约 40 倍，且会把"搜索风格 + rollout 噪声"灌进数据；
DMC 的卖点就是不依赖搜索。

### 3.2 每轮规模（首版）

| 轮次 | 局数 | ε | 预计耗时（8 分片） |
|---|---|---|---|
| R0 冷启动 | 5,000 | — | ~17 分钟 |
| R1 | 10,000 | 0.25 | ~35 分钟 |
| R2 | 10,000 | 0.15 | ~35 分钟 |
| R3 | 10,000 | 0.10 | ~35 分钟 |

实测吞吐：单进程 **0.6~1.1 局/秒**（76~97 决策/局；特征计算只占 0.01s/局，瓶颈是引擎自对弈）；
服务器 12 分片实测合计 **8.8 局/秒**（每片 0.73 局/秒，受 8 个物理核限制）。
采样速率与搜索 AI 无关，可放心多开。

> 实测校正（2026-11-28 01:00）：5k 局 ≈ 10 分钟、10k 局 ≈ 19 分钟，比设计时的估计慢约 20%。

### 3.3 每条样本记什么

```jsonc
{"x": [44 维],                    // stateFeatures（公开信息）
 "c": {"k":"playCard","cost":2,"dmg":0.3,"kill":0,"fast":0,"tgtHp":0.7,"end":0,"sc":1.82},
 "r": 1,                          // 整局回报，按"出招方"视角：赢 +1 / 输 -1 / 平 0
 "g": 12345, "s": 0}              // 局号、座位：只做诊断与按局切分验证集
```

- 只记**实际走的那个动作**（Q 回归只需要它），不记候选全集 → 每条 ~230B，gzip 后 ~60B。
- 一局 40~76 条样本；10k 局 ≈ 55 万条 ≈ 33MB（gz）。
- 落盘：`appendFileSync + gzipSync` 追加（异步 writeStream 会长任务丢数据）。
- 采样率 `--sample=1`（每条决策都记）；如果数据量吃紧再降到 2。

### 3.4 并行与断点

- 8~12 个分片，每片独立文件 `dmc-<shard>.jsonl.gz`，`--start/--games` 切区间；
- 每局结束才落盘 → 崩溃最多丢 1 局；
- 已有文件不覆盖（追加），重跑前清目录或换目录。

## 4. 训练设计

- **目标**：`Q(s, a_chosen) ≈ r`，MSE + Adam，tanh 输出天然有界。
- 输入归一化：按训练集 mean/std（存进权重 JSON，推理端同一个 `policyScores` 会自动套用）。
- **按局划分验证集**（`--val-ratio 0.05`，按 `g` 分组切，不能按样本切——同一局样本高度相关）。
- 超参：batch 1024，lr 1e-3，hidden `64,32`，epochs 3~5。
- **回放池**：R1 训练用 R0+R1；R2 用 R1+R2；R3 用 R2+R3（早期数据分布过时会碍事，最多保留两轮 + 冷启动）。
- **权重版本**：`dmc-q0.json`…`dmc-q3.json`，全部保留（每个 60KB，方便回滚）。
- **离线指标**：
  - `val_mse`：理论上界 4（全错），好模型应 < 0.7；
  - `val_sign`：预测符号与实际胜负一致率，>50% 才算有信号，目标 ≥65%；
  - 额外自检（train_dmc.py 里打印）：验证集上 Q 排序与启发式 `sc` 的相关系数（太低说明没学到行动偏好）。

## 5. 验证设计（三层）

**L1 管线自检**（每轮都跑，1 分钟）
- 采样文件非空、字段齐全、维度 = 44 + 8；
- 训练能收敛（loss 下降）、导出的 JSON 能加载、`dmc` 推理不报错；
- 单决策耗时 < 1ms（DMC 不该比启发式慢多少）。

**L2 离线指标**
- 上表 val_mse / val_sign；若 val_sign < 55%，直接判定这一轮没学到，调 ε 或加数据。

**L3 在线 A/B**（镜像配对：同牌组同 seed 打两局交换先手，`--offset` 分片）

| 对比 | 规模 | 用途 |
|---|---|---|
| DMC vs 纯启发式 | 104 对 = 208 局 | 主门槛（≥55%） |
| DMC vs 冻结搜索 v1@150ms | 104 对 = 208 局 | 是否不退化（≥50%） |
| DMC vs DMC | 52 对 = 104 局 | sanity，期望 50%±10% |

每轮训练后先跑 40 局对启发式的快评（调参用），正式 208 局只在 Q2/Q3 跑。
统计口径：208 局误差约 ±7%，47~53% 视为打平。

## 6. 对接设计

**阶段一（本次）**：只接实验侧。
```bash
# 采样（可并行多分片）
node packages/ai/scripts/dmc-selfplay.mjs --policy=dmc --weights=dmc-q1.json \
  --epsilon=0.15 --games=10000 --shard=0 --shards=8 --out=/data/gitcg/dmc-r2
# 训练
OPENBLAS_NUM_THREADS=1 python3 packages/ai/tools/train_dmc.py \
  --data '/data/gitcg/dmc-r2/*.jsonl.gz' --out dmc-q2.json --epochs 4
# 评测
node packages/ai/scripts/ab-value.mjs --a=dmc --b=heur --dmc=dmc-q2.json \
  --pairs=104 --offset=0 --lib=... 
```

**阶段二（代码已就位，默认关，等达标再开）**：

- `ai-flags.ts` 新增 `dmc: { enabled, model }`：默认关，与策略网络互斥，`model` 为空视为关闭；
- `StandaloneParent.createAiFor` 的优先级变成 **DMC > 搜索 > 启发式**；权重按 URL `fetch` 并缓存，
  加载失败时 `selectAction` 返回 `null`，AiPlayer 自动回退启发式；
- 启用方式（无需改 UI）：把权重放到 `packages/standalone/public/data/dmc-nn.json`，然后在
  localStorage `gitcg.ai.flags` 里写 `"dmc":{"enabled":true,"model":"/data/dmc-nn.json"}`；
- 尚未做：设置页开关、Web 产物重建、APK 重打——等 DMC 过门槛再一次性做。

## 7. 风险与预案

| 风险 | 表现 | 预案 |
|---|---|---|
| 冷启动偏差 | Q 只会打启发式风格，ε 提到 0.3 也救不回 | R2 起淘汰冷启动数据；必要时用"启发式 + 随机"混合采样 |
| 自对弈坍缩 | 双方套路互相克制，对固定基线反而变差 | 每轮都对固定启发式/搜索评测；保留检查点，取最好的 |
| 奖励稀疏、方差大 | val_sign 长期 55% 左右 | 加大 batch/样本；备选：γ=0.99 折扣回报或加血量差 shaping |
| 过估/发散 | loss 爆炸或 Q 饱和 | tanh 输出有界 + 权重裁剪；备选：target network |
| 学的是"运气" | 对启发式过不了 50% | 按局切分验证集、镜像配对评测、扩大样本 |
| 特征泄漏 | 对搜索结果虚高 | 前置修正 `deckPriorDiff`；再查一遍其它维度 |
| 平局 | 15 回合上限，偶发 | 记为 0，不特殊处理 |

## 8.5 样本量校准（为什么 v0 只是基线）

- DouZero 的结果是 **48 核 + 4 卡、约半天**才超过启发式，折算下来是 **百万局级** 自对弈；
- 我们的吞吐：单进程 0.7~1.1 局/秒，12 分片 ≈ **8.8 局/秒 ≈ 76 万局/天**；
- v0 计划 5k 冷启动 + 3×1w = **3.5 万局**，只有 DouZero 规模的 2~3%——所以 v0 的目标是
  **验证管线 + 拿到第一个可信数字**，不是"一把超过搜索"；
- 若 v0 对启发式 ≥ 50%（不退化），下一步直接扩到 **20~40 万局**（6~10 小时服务器时间，¥13~20），
  用同一套链（把每轮局数换成 2~3 万、轮数加到 6~8）。

**Q0 行为诊断**（445,953 条启发式样本训练，20 局 1084 个决策）：
与启发式首选一致率仅 **38.2%**（第 1 名 414、第 2 名 120、第 3~5 名 208），
说明网络不是简单模仿启发式；但 40 局快评只有 50%，说明这些偏离目前还没有转化为优势——
符合"样本量不足、自对弈还没开始"的判断。
