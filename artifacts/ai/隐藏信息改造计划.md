# 搜索的真实隐藏信息改造（2026-11-27 22:50）

## 问题
`search.ts` 的 `searchBestAction` 接收的是 `game.state`（核心态），
`determinizeState` 只是把对手**真实**的剩余牌在手牌/牌堆之间重洗。
→ 搜索在偷看对手手牌，A/B 与 App 里的搜索强度都有虚高成分。

对照：启发式 AI 拿的是 `exposeState()`（只看到手牌数量），是正常受限的。

## 现状核查（22:48）
- `packages/core` 没有公开的“按卡牌 id 创建手牌实体”的 API
- `createEntity` 只存在于 `SkillContext` 内部（触发技能/召唤物时用）
- `exposeEntity` 只做暴露，不做创建

## 改造方案（三步）

### 1. core：加一个便宜的实体构造器
在 `packages/core/src/utils.ts` 或 `state.ts` 增加：

```ts
export function createCardEntity(state: GameState, definitionId: number, who: 0|1): EntityState
```

只需要：`id`（唯一）、`definition`（从 data 取）、`variables`（默认）、
`attachments: []`、`area: { who, type: "hands", cardId }`。
约 40~60 行，风险低（不参与现有结算路径）。

### 2. ai/search.ts：determinizeState 改为“重建”而非“洗牌”
- 公开信息：对手角色（公开）、手牌数、牌堆数、已出牌、我方已知牌
- 卡池：与对手角色相容的卡牌（`relatedCharacterId` / `relatedCharacterTag` 校验）
- 权重：`handLikelihood` × 牌组库先验（同一角色组合的常见牌）
- 排除：对手已打出的牌（按剩余张数扣减）
- 用 `createCardEntity` 造出 `handSize + pileSize` 张牌，再按权重分成手牌与牌堆
- **不再读取 `enemy.hands` / `enemy.pile` 的真实内容**

### 3. 重新标定
改造后 AI 会变弱，所有搜索类数字作废，必须重跑：
- 搜索 vs 纯启发式（208 局）
- 150ms vs 600ms（208 局）
- 跳过预览 vs 完整预览（208 局）

## 影响面
- A/B 框架：无需改动（它本来就传核心态）
- App：无需改动（`search.worker` 同样传核心态）
- 采集：特征本来就是公开信息，不受影响
- 训练：不受影响

## 预期
按今天的经验（rollout 数是主要因素），屏蔽信息后搜索的 rollout 质量会下降，
预计搜索 vs 启发式从 60.7% 回落到 53~56%，需要实测确认。
