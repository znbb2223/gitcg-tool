## 待做（排队）
### 中等：成对排序目标
- 现状：价值网络学"绝对胜负概率"，但搜索需要"候选之间的相对优劣"
- 方案：同一局面取两条不同后续，训练 pairwise ranking（hinge / BPR loss）
- 数据：v3 的 `c` 字段没有后续局面，需要新采集（每决策点额外采 2 条后续特征）
- 成本：改采集器 + 改训练脚本 + A/B，约 1 天

### 较贵：rollout 叶子采样
- 现状：样本采自"决策点"，搜索评估的是 rollout 截断叶子
- 方案：在 search 的叶子评估处回调采样（已有 `onSample` 钩子），落盘训练
- 成本：采集开销 +30~50%，单局从 4 秒到 6 秒

### 数据修复（已完成采集器改造，需重采）
- `e` 字段（对手已出牌）原来 99% 为空，核心态 `removedEntities` 没填充
- 已改为从动作流抓取双方出牌，验证 0~5 张正常分布
- 贝叶斯读牌要等这批新数据

# 待办补充（2026-11-27 22:52）

## A. 对手信念建模（含隐藏信息改造）

**目标**：让搜索只用玩家真实可见的信息；并在此基础上用贝叶斯/统计先验提高确定性化质量。

**已完成的可行性判定**
- 只看对手已出牌 → 候选牌组仍是 4,543 套（无信息）
- 已知对手三角色 → 候选牌组中位 **2 套**
- 三角色 + 1 张已出牌 → 基本唯一确定
- 结论：信息充足；但**当前引擎给搜索的是全知态**（真实手牌），所以现状是“作弊强度”

**第一步：给 core 加实体构造器**
- `createCardEntity(state, definitionId, who)`（约 50 行，不参与现有结算）
- 新增开关 `search.realisticHidden`，**默认关闭**，先保证现有链路不变

**第二步：重写 determinizeState**
- 卡池 = 与对手角色相容的牌（`relatedCharacterId` / `relatedCharacterTag`）
- 排除对手已出牌（按剩余张数扣减）
- 权重 = `handLikelihood` × 牌组库同角色组合的常见牌先验
- 造出 `handSize + pileSize` 张牌，按权重分到手牌/牌堆
- **不再读取 `enemy.hands` / `enemy.pile` 的真实内容**

**第三步：重新标定（关键）**
- 改造后所有搜索类数字作废，必须重跑：
  - 搜索 vs 纯启发式 208 局
  - 150ms vs 600ms 208 局
  - 跳过预览 vs 完整预览 208 局
- 预期：搜索 vs 启发式从 60.7% 回落到 53~56%，需实测

**第四步：信念采样（可选增强）**
- 用 v6 数据（`e` 已修好）统计“什么牌更容易留在手里”
- 替换 `handLikelihood` 的拍脑袋权重为数据学出来的权重
- 208 局 A/B 对比

**数据资产**：`/data/gitcg/traj-v6`（480 局 / 20,777 条，44 维 + 牌组索引 + 对手已出牌）

## B. 社区攻略收集与知识提炼

**目标**：把社区攻略转成 AI 能用的先验/规则，而不是直接喂文本（AI 没有文本输入通道）。

**四阶段流程**

1. **抓取**
   - 米游社：已有 `scrape-miyoushe.mjs`（关键词：牌组/卡组/构筑/赛事/冠军/分享码）
   - 贴吧：需新写抓取器（文字帖）
   - 官网：规则与版本更新（新卡数值）
   - B 站：视频内容抓不到，只能取标题/简介作弱信号
2. **结构化**：每篇提取 → 角色组合、留牌建议、核心 combo、克制关系
3. **交叉验证（最关键）**：与自有 2 万局统计对照，**只保留两边一致的结论**
   - 依据：今天实测“凭直觉的先验”多为零或负（静态先验 51.3%、学习先验 52.6%）
4. **注入 + A/B**：只把验证过的规则写进 `cardPrior` / `author-hints`，208 局确认正收益才上线

**已完成的历史验证（参考）**：`_ab-hints.mjs` 曾实测 80 局 47.5% → 55%（带攻略提示），
但样本小，需要扩样确认。

**输出物**：
- `artifacts/ai/攻略知识库.md`（结构化条目，带来源与日期）
- 与数据冲突的条目单独列出（这类最有情报价值）
