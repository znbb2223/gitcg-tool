## 二、依赖关系

**依赖顺序**：① 规则引擎是底座；② 启发式 → ③ 搜索 / ⑧ 策略网络；③ 与 ⑥ 价值网络共用同一批数据；
⑨ 双头合并 ⑥/⑧ 后进入 ⑩ 迭代自对弈；④ 决策记忆、⑤ 经验统计、⑦ 查表价值、⑪ 贝叶斯、⑫ 进化调权重、
⑬ LLM 均为独立支线（⑫ 只调 ②，⑬ 不参与下棋）。

## 三、阶段与门槛

### 🅐 基础设施（已完成）

- 采集器：自对弈 → JSONL，**v5 格式**（40 维向量 + 胜负 + 候选动作 + 牌组索引；gzip）
- 训练器：numpy MLP（40→64→32→1），全量 59 万条约 1 分钟；**必须单线程 BLAS**
- 策略网络训练器：`tools/train_policy.py`（带掩码 softmax + 交叉熵）
- 推理：`nnValue` / `policyScores` 纯 JS 前向，0.1ms，维度不匹配自动回退
- A/B：同牌组交替先手对打，支持 `--policy/--heur/--memory/--perfectInfo/--budgetB/--priors/--skipPreview`
- 打包：esbuild 单文件 bundle（服务器零依赖）

### 🅑 价值网络闭环（✅ 已闭环，结论：不达标）

| 步骤 | 内容 | 状态 |
|---|---|---|
| B1 | 采集 20,000 局 / 593,030 条 | ✅ |
| B2 | 训练 40 维模型（val 72.8%） | ✅ |
| B3 | A/B 合计 **1,040 局 = 51.1%**（±3.1%，p≈0.25） | ✅ 未过 53% 门槛 |
| B4 | 开关 + 设置页 | ✅（默认关闭） |

**结论**：离线准确率涨 4.6 点，实战不动。精度分层显示胶着局面仅 68% 准确率，
已定局面 93~100%——整体准确率被「垃圾题」抬高。**保持默认关闭。**

### 🅒 查表价值（❌ 数据判死）

同一批数据分桶（每维 4 档）→ `FeatureTable` → 拉普拉斯平滑。
目的：给不跑网络的设备一个中间档，并与 6 做 A/B 对比。

**实测**：59.3 万条样本落进 55.2 万个桶，平均每桶 **1.07 条**；
桶内 ≥30 局（`tableValue` 的最低要求）的样本只占 **3.8%**。
→ 现状下 96% 的局面查表返回 null。要救必须先改分桶策略（少取几维或哈希降维）。

### 🅓 策略网络（需要带搜索标签的数据）

| 步骤 | 内容 |
|---|---|
| D1 | 采集 5 万局，动作标签来自搜索 AI |
| D2 | 训练 state-action 打分器（交叉熵） |
| D3 | 推理 O(N) 次前向 + 合法性掩码 |
| D4 | A/B：0ms 策略 vs 100ms 搜索 |

**门槛**：0ms 出招 ≥ 搜索 100ms 水平。

**实测结论（❌ 未达标）**：

| 版本 | 训练标签 | 对启发式胜率 |
|---|---|---|
| 含 sc | 启发式 4.1 万条 | 48.0% |
| 含 sc | 搜索 9.8 千条 | 44.2% |
| 去 sc | 启发式 4.1 万条 | 36.7% |
| 含 sc | v3 子集 28.5 万条 | 1.0%（候选语义不匹配） |
| 作为搜索先验 | 启发式标签 | 46.9%（稀释了 rollout 权重） |

**根因**：模仿学习的上限就是老师；且「离线 top-1」与实战强度脱钩
（离线最高 80.4% 的那版实战最差）。**要超过老师，标签必须换成最终胜负，即 DMC 路线。**

**为什么用打分器而不是分类器**：TCG 合法动作数量变长（3~30 个），
打分器天然处理变长输入，且非法动作不会被采样到。

### 🅔 双头 + 迭代

- 双头：共享主干 + 两个输出头（策略 logits / 价值 tanh）
- 迭代：用当前最强配置产 5 万局 → 重训 → 比较

**门槛**：每轮胜率提升 ≥ 1%。

## 五、设计原则

1. **默认安全**：新组件默认关闭，A/B 不过关不上线；
2. **可回滚**：每个组件独立开关 + 模型版本号；
3. **不联网**：模型编译进包或本地导入；
4. **解耦卡池**：价值网络只用统计特征，不绑定卡牌 id，
   官方更新卡池后**无需重训**即可继续使用。

## 六、2026-11-27 实测后的方向修正

累计约 6,200 局镜像配对实验后，结论非常集中：

| 维度 | 实测 |
|---|---|
| 搜索 vs 纯启发式 | **60.7%**（798 局）✅ |
| 跳过 rollout 动作预览 | **63.9%**（416 局）✅ |
| 预算 600ms vs 150ms | **75.7%**（415 局，sanity 已复核）✅ |
| 深度 30 vs 10 | 51.9% ⚪ |
| 价值网络（1,040 局） | 51.1% ⚪ |
| 静态/学习先验、记忆、查表、策略网络 | 全部 ≈0 或负 ❌ |

**规律：rollout 数每翻一倍，胜率约 +12~13 点。** 150ms 只有 1.3 个 rollout，600ms 约 5 个，
跳过预览后单次成本从 112ms 降到 34ms。

### 因此优先级调整为

1. **继续压低单次 rollout 成本**（已做：跳过预览；可做：动作枚举剪枝、determinize 抽样优化）
2. **在有效算力区间（600ms+）重测一切**——此前所有「模型无用」的结论都来自 1.3 个 rollout 的区间
3. **DMC 自对弈**（DouZero 路线）：用整局胜负作标签，无需老师；见
   [`artifacts/ai/游戏AI资料汇编.md`](../artifacts/ai/游戏AI资料汇编.md)
4. **不要**再做：模仿式策略网络、进化调权重、查表（除非改分桶）
